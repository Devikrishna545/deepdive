# Key design decisions

Short notes on the choices that matter for trust, cost and the hackathon rules. Update this
file when a decision changes; the README links here.

| # | Decision | Why | Alternative rejected |
| --- | --- | --- | --- |
| 1 | **Claim-level verification**: the drafter emits atomic claims; the verifier checks each one against only the chunks it cites | A sentence-level or report-level check can't say which fact is wrong; atomic claims make rejection precise and explainable | Ask one LLM to "review the report" |
| 2 | **Verifier isolation + different model family** (`MODEL_VERIFIER` ≠ drafter family) | Prevents the verifier from being persuaded by the draft or by its own earlier reasoning | Same model self-critique |
| 3 | **Quote guard in code**: evidence quote must appear verbatim in the cited chunk | Stops the verifier itself from hallucinating support; cheap and deterministic | Trust the verifier's label |
| 4 | **Citation check in code** after synthesis | The synthesizer can still add a flourish; code deletes any sentence without a verified claim ID and logs it | Prompt-only instruction |
| 5 | **Coverage gate + bounded loop** (≥ 2 verified claims from ≥ 2 domains, `MAX_LOOPS`=1 by default to save credits) | Thin topics get more research instead of padding; the bound protects cost and latency | Unbounded "research until good" |
| 6 | **Gap queries from rejection reasons** | The loop learns from why claims failed (weak source, missing number) rather than repeating searches | Re-run the same queries |
| 7 | **Coordinator is code (LangGraph), agents are LLM calls** | Routing, fan-out, loop counting and citation checks are testable and deterministic | An LLM "manager" agent |
| 8 | **Mesh through the official OpenAI SDK in one module** (`app/llm/mesh_client.py`) + CI check | It is exactly the client the brief shows and the one its checks look for in `requirements.txt`; one choke point makes "every call goes through Mesh" provable by grep; we see every request's exact tokens (cost tracking, `max_tokens` caps, retry only on transient errors, never on 402); JSON-mode + Pydantic works on every model family behind the gateway, while LangChain's `with_structured_output` relies on tool/json-schema support that not every gateway model has, and its embeddings wrapper tokenises with tiktoken. LangGraph does not need LangChain models: nodes are plain functions. Swapping in `ChatOpenAI(base_url=Mesh)` later is a one-file change | LangChain chat models across the code |
| 9 | **JSON mode + Pydantic validation + one repair retry** | Works across model families on the gateway, including ones without strict structured outputs | Provider-specific function calling |
| 10 | **Source-quality weighting as a visible table** (`app/core/scoring.py`) | Judges can read the trust policy; easy to tune | Hidden prompt instruction |
| 11 | **SQLite for runs, trail and caches; numpy vector store for uploads** | Zero ops for a 6-day build; search/fetch cache makes eval reruns cheap and comparable | Postgres, Chroma (heavier install) |
| 12 | **Server-rendered HTML + vanilla JS UI** served by FastAPI (Tailwind CDN replaced by one stylesheet on 18 Oct, see 33) | One process, no build step, full control of citation marks and the trail view | Streamlit (less control over the report layout) |
| 13 | **Ablation switch** `VERIFY_ENABLED=false` | Lets us measure what verification contributes with the same pipeline | Compare against a different system |
| 14 | **Independent judge model** for groundedness in the eval | The system shouldn't grade itself with the model it used to filter | Use the verifier's own pass rate as the score |
| 15 | **Credit guards from Mesh's own APIs**: balance from `GET /v1/balance` before every run (warn < $5, refuse < $1), live prices from `GET /v1/models` to price every call, `RUN_BUDGET_USD` per run, loop-back skipped after 60% of the run budget | Small balance; a run should finish with a report rather than be cut off, and spend must be visible per step | Discover the balance when calls start failing with 402 |
| 16 | **Cheap models for volume, the stronger model only for the verifier** | Claim accuracy is decided in the verifier; planning, extraction, drafting and writing from verified claims are well within `gpt-4o-mini`-class models, and code guards catch their mistakes | Strong model everywhere |
| 17 | **Token discipline**: compact output-shape hints (~80% shorter than JSON Schema), short prompts, `max_tokens` on every call, drafter sees findings not chunks, 10 chunks × 700 chars per sub-question (Markdown links stripped), contradiction check only on numeric/date claims | Same accuracy contract at a fraction of the input/output tokens | Long prompts and full schemas |
| 18 | **Free verbatim fast path in the verifier**: a claim equal to a whole source sentence is accepted by code | Zero-cost and exact; whole-sentence equality (not substring) keeps it safe against negated contexts | LLM call for every claim |
| 19 | **A failed writing step falls back to a code-built report of verified claims** (and stray non-object items in the synthesizer's lists are dropped before validation) | A live benchmark run lost a fully verified run ($0.02) because `gpt-4o-mini` leaked `"limitations:["` into the sections list twice. The fallback still contains only kept claims, each cited, and says in Limitations that it was built without the writer | Fail the whole run |
| 20 | **Reply cut off at `max_tokens` → one retry with a 1,200-token cap**, instead of a repair round | Half-written JSON can't be repaired by the model that ran out of room; this also covers "thinking" models (the Gemini judge) that spend the cap on hidden reasoning | Larger caps on every call |
| 21 | **Search outage stops the run before drafting** (`NoEvidence`), and the benchmark checks search for free before any paid call | DuckDuckGo rate-limits parallel queries and answers "No results found"; without a stop, runs paid for planning and an empty report. Tavily (free tier) is the recommended provider | Keep running with no evidence |
| 22 | **Page text is cleaned of Markdown before chunking; the quote guard compares visible text and accepts "..." only for in-order pieces of one chunk** | Benchmark 1: 18 of 24 quote-guard rejections were true claims whose quote matched the page but not its `[text](url)` markup; this removed 2 key facts. Cleaning also cut chunk text by 16%. The guard is no looser: every piece must be in the same chunk, in order, and one piece alone must be >= 12 chars | Loosen the guard to fuzzy matching |
| 23 | **Premise check is guaranteed by code**: the planner names an assumption that may be false, code adds "Is it true that ...?" as the first sub-question, and the synthesizer must open with the correction when the evidence contradicts it. Section headings are the sub-question texts, set by code | Benchmark 1 (b08) wrote headings like "Reasons Behind the EU's Decision to Ban Petrol Cars"; headings were the one piece of model text not tied to a verified claim | Trust the planner prompt alone |
| 24 | **Source tier shown next to each claim for the synthesizer** (`[clm_x] (official)`), with "prefer official on conflict" | The verifier checks that a source says something, not that the source is right; a blog's "the EU abandoned the 2035 ban" passed. Tier labels let the writer prefer the Commission page and state the conflict | Extra LLM pass to fact-check sources |
| 25 | **More evidence per sub-question (3 chunks per page, 10 per sub-question, 10 findings), ranked against the main question with a bonus for passages containing figures** | 7 of 8 facts lost before extraction were on a page we had fetched but cut at the 2-per-page / 8-per-sub-question limit. Paid for by the 16% shorter chunks and a shorter verifier reply (reason <= 12 words, shortest quote) | Fetch more pages |
| 26 | **Claim ids in the writer's reply are parsed by code (`clm_[0-9a-f]+`), tiers shown as `[clm_x] (official)`** | Benchmark 2: with `[clm_x|official]` the model copied `clm_x|official` as the id, and the citation check (correctly) deleted all 10 sentences of b06. Parsing the id is format handling; the citation check still requires every id to be a kept claim | Loosen the citation check |
| 27 | **Premise-check claims are compared official vs non-official, for every claim type; a contradicted blog/industry claim is superseded by code** (a `CONTRADICTED` verdict with the official claim as reason, visible in the Claims tab). News is flagged, never removed | Benchmark 2 (b08): a blog's "the EU has abandoned its 2035 ban" was verified (the blog says it) and reached the report. Status conflicts are prose, so the number/date-only contradiction check missed them. Cost: at most 3 short pair calls per run, only when a premise check exists. News isn't removed because a recent report can be right about a change an official page predates | Fact-check every claim with a second LLM pass |
| 28 | **Plans are cached per question, depth, planner model, prompt text and month** (`CACHE_PLANS`) | Benchmark 1 vs 2: single questions swung by a fact either way with no relevant change, mostly because the planner wrote different sub-questions and so different searches. Same plan -> same queries -> cached search, so reruns measure what changed downstream, and a repeated question costs no planner call. Changing `prompt.md` or the model changes the key | Run every benchmark several times |
| 29 | **Planner covers the question's own parts first; researcher extracts facts for the main question too; drafter never drops a finding with a figure, date or law name** | Benchmark 2: one of three quick-depth slots often went to generic angles ("Who are the main stakeholders") the question didn't ask; 4 key facts sat in fetched chunks but were not extracted because they answered the main question rather than the sub-question's wording | More sub-questions (more cost) |
| 30 | **A verified figure the writer left out is added to its section by code when another kept claim from a different passage states the same figure** (`app/core/key_claims.py`; years don't count; max 2 per section; skipped if cited or if its figures are already in the report) | Benchmark 3: 6 of 13 missing facts were verified and kept but not written (b05 kept the US 176 TWh figure and dropped the global 415 TWh / 1.5%). Replayed on the stored runs: 9 added sentences over 10 reports recovered both b05 facts; adding every uncited figure added 46 for the same gain, and word-overlap ranking could not tell key from background. The added sentence is the kept claim, cited to itself, and the citation check still runs | A second writer pass (more cost, same risk) |
| 31 | **Planner uses only years and places the question states, and writes no sub-question that assumes a premise; for rules, one query names the official law. Drafter takes years and numbers only from the finding; researcher keeps the period the source gives and extracts an official body's main conclusion** | Benchmark 3 (b05): the planner invented "consumption in 2020", the drafter wrote "In 2020, data centres consumed 415 TWh" (the source says 2024) and the verifier rightly rejected it, losing a true fact. b08 still had a section on "reasons for the ban" that never happened. 5 facts were never retrieved, mostly law numbers (b01, b10) | Relax the verifier on years (never) |
| 32 | **Planner on a cheap reasoning model: `openai/gpt-5-nano` ($0.05 in / $0.40 out per 1M), falling back to `openai/gpt-oss-120b` ($0.15 / $0.60) if the call errors or returns no valid plan. Planner caps raised to 2500 (plan) / 1000 (gap queries)** | Benchmark runs 1-5 swung from 55% to 77% key-fact coverage mostly on plan quality: wrong years in queries ("2026" for a 2023 IPCC report), sub-questions that assume a false premise. Those are reasoning mistakes, and the planner is 1-3 short calls per run, so thinking is cheap here (estimate under $0.001 per question including hidden reasoning; the verifier is ~$0.017). Both models are cheaper or equal per token than gpt-4o-mini. Hidden reasoning counts against max_tokens, hence the larger caps. The fallback lives in `mesh_client.chat_json(fallback_model=...)` and never fires on a 402 (no credit). The planner sends `reasoning_effort=low`: at its default effort gpt-5-nano spent all 2500 tokens thinking and returned an empty reply on every question of the first live run (each fell back to gpt-oss-120b). An empty reply now goes straight to the fallback without a repair round | Keep gpt-4o-mini and tune the prompt (run 5: one prompt edit cost 22 points); o4-mini (about 7x the price) |
| 33 | **UI redesign: one hand-written stylesheet (pastel palette, light and dark), local Lucide icons, an evidence panel that highlights the exact words the verifier quoted, installable as an app (PWA)** | The judged differentiator is trust, so the most visible element is the proof: click a citation and the passage opens with the quoted words highlighted, plus the verdict, the source type (official / academic / news / web) and a link. Removed claims are one click away from the report header. The Tailwind Play CDN is meant for prototypes (runtime compiler, slow first paint, no offline); one stylesheet and a 10 KB icon sprite load fast and work offline. Pastel fills carry state; text on them uses a deeper ink of the same hue for AA contrast. One responsive web app covers phone, tablet and desktop, and installs to the home screen; the service worker caches only the app shell, never `/api` | A React/Next.js rewrite (build chain, two days left); native apps |
| 34 | **Planner model switched to `openai/gpt-oss-120b` (fallback `openai/gpt-5-nano`); queries must name the subject with its field** | Run 7: with every plan made fresh by gpt-5-nano, coverage fell from 78% to 50% with nothing else changed (a premise check on "data centers use electricity", "TODAY" inside queries). A live run on transformers showed nano copying the prompt's checklist into sub-questions ("Figure: identify key figures…") and searching "What magnitude constitutes breakthrough today". gpt-oss-120b made the strong plans in run 6, costs the same as gpt-4o-mini per token and is also a reasoning model. The prompt no longer lists words that can be copied as headings | Keep nano and tune its prompt |
| 35 | **Hybrid ranking: meaning (Mesh embeddings, `text-embedding-3-small`) + keywords.** Search results are checked for meaning before fetching (off-topic ones skipped and logged); passages are ranked 0.5 x keywords + 0.5 x meaning | Keyword overlap alone cannot separate the two meanings of a word: the transformers run cited the US Department of Energy on power transformers, an earthquake-magnitude page and Federal Reserve interest rates. Embeddings are about $0.02 per 1M tokens (well under a cent per run), go through Mesh like every other model call, and fall back to keywords if they fail. Keywords stay in the mix because exact law numbers and figures matter for verification | Embeddings only (loses exact-match strength); an LLM relevance pass (cost) |
| 36 | **Evaluation: `--ablation` runs the normal set and the verification-off set in one call; judge calls get room to think (4000 tokens, low effort; a reply that still fails is counted as a judge error, not a crash). `DEV_MODE` defaults to off** | `write_results` replaces the README block, so two separate calls left only the last table, and the ablation is only meaningful next to the normal run on the same plans (the plan cache makes both use the same sub-questions and searches). The judge is a thinking model that stopped before answering at 100-250 tokens (the benchmark judge failed the same way), and at 1500 one long report cut off mid-JSON and crashed the whole evaluation. Judges should see the product, not the developer token views | — |
| 37 | **Fixes from the Playwright test round (functional 29/30 pass, accessibility scan clean in light and dark):** runs made with verification off show citations and claims as **Not verified** (grey), never as verified; a failed run marks the step that failed and gives a plain reason; empty, scanned or damaged uploads are refused with a message instead of being silently empty; short notes in uploaded files are kept; the add-documents control and the report tabs work by keyboard (arrow keys); tabs fit phone widths down to 320 px; unknown runs get a 404 page; `<CHUNK>` tags inside fetched text are escaped before reaching a prompt; requirements are pinned to exact versions | The report is the product and trust is the claim, so an unchecked claim must never look checked (the ablation runs are stored next to the real ones). The rest were defects a judge could hit in a first minute of use | — |
| 38 | **Optional hosting guards: `RUN_ACCESS_CODE` (header `X-Access-Code`, compared in constant time) and `MAX_RUNS_PER_DAY`, plus security headers** | A public demo link lets anyone spend the Mesh credit (each run ~$0.02-0.04); 25 run requests in a burst were all accepted in testing. One shared code and a daily cap are enough for judges and keep the no-accounts scope. Both are off by default so local use is unchanged | User accounts (out of scope); a CAPTCHA |
| 39 | **Follow-up research is a new run linked to the earlier one** (`parent_run_id`): the planner gets the earlier questions and up to 12 verified findings as context and returns a standalone question; the earlier report's cited passages join the researcher's candidate pool; every claim is verified again | A finished report was a dead end: a follow-up ("and in India?") had to be typed as a full new question and researched from zero. Carrying context through the planner (one call, ~600 more input tokens) resolves references; reusing passages saves search and fetch. Only kept claims and their passages carry over, so a removed claim can never return, and re-verifying keeps the rule that nothing reaches a report without a check in that run. A separate run keeps each report, audit trail and cost on its own | Append the follow-up to the same report (mixes two questions and two audit trails); send the whole earlier report to every agent (cost, and the drafter would see claims it did not source) |
| 40 | **Edit & run again starts a new run; the original is kept. Delete removes a run with its audit trail, one at a time or by selection, after a confirm dialog** | A typo or a missing year in the question meant typing it all again, and the home list only grew. Rerunning as a new run keeps every report's audit trail true to the question it answered (editing a finished run in place would leave a trail for a different question). Both act only on finished runs: a running run still has a background thread writing to it, and a second run started early would spend credit twice. On a hosted demo, deleting needs the same access code as starting research, so a visitor cannot wipe the list. Cached search results and uploaded documents are shared with other runs and are not deleted | Edit the question in place; cancel a running run (needs a stop signal inside the graph) |
| 41 | **Stop a run in progress: checked by code before every step (`RunStopped` in `traced`), status `stopping` -> `stopped`; the editor opens at once and the corrected run can start while the old one finishes its current step** | Waiting minutes for a run you already know is wrong wastes credit and time. A check before each node needs no threads to be killed and leaves a clean audit trail; a model call already sent cannot be recalled, so the run stops at the next step boundary. Work done so far is reused only where it is still valid for the new question: searches and fetched pages are cached per query and URL, so overlapping queries cost nothing; plans, drafts and verdicts belong to the old wording and are not carried over, because a claim must be verified for the question it answers | Carry the stopped run's partial claims into the new run (they were drafted for a different question); kill the thread (unsafe mid-write) |
| 42 | **Document mode: when files are attached and the question refers to them ("this paper", "the attached report", "our documents"), answer from the documents only** (`app/core/doc_mode.py`): planner sees the documents' opening text (`documents_prompt.md`), no premise check, no web search, the first 2 passages (title page) are always candidates, 8 retrieved passages per sub-question with no per-source cap, and one domain passes the coverage gate | A live run on "what are the computational optimizations done in this attached paper?" (word2vec PDF) answered "title / authors / contributions" with "No claim passed verification": the planner could not know which paper "this" was and searched "paper title", "paper authors"; 53 of 60 passages came from unrelated web pages (a 2013 Procedia paper, a Fermilab authorship policy) and only 7 from the PDF, capped at 3 per source; the title page was never retrieved; and the two-domain rule sent every section back to the web. Detection is a regex on the question plus attached files, so runs without documents (the benchmark and evaluation) are unchanged; the normal planner prompt is byte-identical. An empty section whose sub-question has kept claims now says so instead of "No claim passed verification" | Let the planner decide web vs documents (another output field and a guess); always search both (the failure above) |
| 43 | **Optional web add-on for document mode ("Also search the web", stored as `web_addon` on the run): every research step reads the documents and the web, documents first** - up to 6 of the 10 passages per sub-question are reserved for the documents (`DOC_PRIORITY_SLOTS`), the web fills the rest; one web query names the document's title; the writer sees document claims labelled `(document)` and listed first; follow-ups inherit the choice | First version searched the web only in the loop-back round for sub-questions the documents left thin. On the live site that meant the toggle did nothing for questions about a paper (the paper answers them well enough, so nothing looped back), and follow-ups such as "how did later work compare?" stayed document-only. Reserving slots keeps the priority honest without an extra model call; the label is code-set from the cited passage's source. Off by default, so document mode without the toggle is unchanged | Web only for thin parts (the first version); rank documents and web together (the web, with more pages, crowds the document out) |
| 44 | **Report writing safety net: the writer writes one sentence per item; a section it leaves empty although its sub-question has verified claims gets up to 3 of them by code (figures first, verbatim, cited to themselves); the report shows one citation marker per source per sentence ("1", not "1 1 1 1 1") that opens all the claims behind it** | Review of the 40 most recent stored reports: 11 had a section left empty with 3-10 verified claims behind it while the coverage gate said "coverage ok", and almost every executive summary came back as ONE item holding 3-5 sentences, so its claims stacked up as repeated markers at the end. Replaying the fill on those runs added 50 sentences, all verified claims of the right sub-question (e.g. the EU AI Act GPAI obligations and definition). The added text IS the kept claim, so nothing unverified enters, and the citation check still runs. Reports already stored are not changed; evaluation numbers in this README come from runs before this change | Re-ask the writer (another paid call); hide empty sections (hides verified evidence) |
| 45 | **Deployment: one `Dockerfile` (Python 3.12, non-root user 1000, port from `PORT`), Hugging Face Spaces free tier via `scripts/deploy_hf_space.py`, optional `FRAME_ANCESTORS`** | Spaces gives 16 GB RAM, secrets in its settings and a stable URL for free; Render's free 512 MB tier sleeps after 15 minutes. The Space page shows apps inside an iframe on huggingface.co, which our `frame-ancestors 'none'` / `X-Frame-Options: DENY` would block, so the allowed parent is a setting (empty by default = no framing). The script uploads only git-tracked files (never `.env` or `data/`) through the Hub API, which handles the PNG icons without git-lfs; secrets are added by hand in the Space settings. Checked by running the image's exact command in a clean Python 3.12 environment built from `requirements.txt` only. Document uploads now return 503 with a plain message when the model service is unreachable (they need embeddings), instead of a 500 | Render free tier; a VM |
| 46 | **Quote guard compares text as read, not as typeset; PDF text is cleaned when passages are built; the run page says "Documents only" or "Documents first + web"** - ligatures (NFKC), words hyphenated across lines, a hyphen left inside a word, and a space before punctuation are ignored on both sides; a quote listing items ("Tomas Mikolov, Kai Chen, ...") is checked like a "..." quote (every piece in the same passage, in order, one piece of 12+ characters); the verifier may join separate exact pieces with " ... " | Live run on the word2vec PDF: the authors and 6 other claims the verifier had SUPPORTED were removed by the quote guard because the PDF said "signiﬁcantly", "repre-\nsentations" and "in , with", and the title page lists each author with an affiliation and email. Replayed on the 24 guard removals in the last 25 stored runs: 14 now pass (all checked by hand: true quotes), 10 stay rejected (the verifier edited the source's words, e.g. skipped a clause, or quoted the wrong passage). Fabricated names, wrong order and fragments still fail (`tests/test_pdf_quotes.py`). The mode chip makes the web setting visible: a re-run kept a run's earlier "web off" choice, which looked like a bug | Fuzzy matching (would let near-misses through); dropping the guard for documents |
| 47 | **Edit & run again and Continue this research can change the documents: the run's documents are listed (removable), more can be added, and the web switch appears whenever a document is listed; the new run uses exactly the documents shown** (`file_ids` and `web_search` on `/rerun` and `/followup`; omitted = the earlier run's) | A follow-up often needs a second source ("what does this other report add?"), and a fix to a question often includes the attachment ("I uploaded the wrong file"); both previously meant starting over from the home page and losing the thread. New files upload only on submit and are kept if the run then fails to start, so a retry doesn't upload twice. Removing every document stores the web switch as off, since it only applies to document questions. Tested end to end in the browser (remove one, add two, unsupported type skipped, follow-up adds a third; all three cited) | A separate "attach to this run" action (changes a finished run's evidence after the fact) |
